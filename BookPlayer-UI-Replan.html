UI / UX 重新规划 · 清新优雅版 v2

BookPlayer 界面重新规划方案

基于 TortugaPower/BookPlayer 源码盘点，融合参考原型 Lumina Listen 的清新优雅基调，对界面做第二版重设计：统一柔和青绿 + 暖金的设计语言、衬线标题、柔和阴影与留白，并修正播放器布局（回归原版合理的垂直结构）。

平台：iOS / iPadOS / watchOS / CarPlay / 小组件 技术栈：UIKit Coordinator + SwiftUI 混合 基调：清新优雅 · 柔和青绿 #8FCBA8 + 暖金 #E6C49B 盘点文件：120+ UI 文件
💡 本轮改动说明（回应你的两点反馈）：① 播放器布局已修正——不再把「快退/睡眠/书签/快进/倍速」塞进一个玻璃条，改回原版合理的垂直流（大封面 → 章节导航 → 进度 → 传输行 → 底部 5 个快捷动作）；② 整体改为清新优雅风——柔和配色、衬线标题、渐变封面、柔和阴影与大圆角，并支持日间/夜间一键切换。

01现状界面盘点

应用以 UIKit Coordinator 模式为外壳，内部主界面已全面转向 SwiftUI。真正的应用外壳是 MainView.swift 中的 TabView（全应用唯一标签栏），由 MainCoordinator 以全屏模态覆盖在 UIKit 导航控制器之上。

真实播放器结构（关键，布局合理）

读源码确认 PlayerView.swift 的实际垂直顺序为：大封面（书名/作者印在封面上）→ 章节导航行（上/下一章 + 章标题）→ 进度条 + 时间 → 传输行（后退/播放/前进）→ 底部安全区 MediaActionRow（speed / timer / bookmark / chapters / more）。这是一个标准、合理的听书播放器布局，第二版原型据此重建。

02核心问题诊断

从界面工程与体验角度，按影响程度排序。

HI 双范式外壳 + 死视图层

RootViewController / Main.storyboard 作为初始根却被 MainView 全屏模态覆盖，其容器视图已废弃。

HI 三套近似重复的媒体服务器界面

Jellyfin / AudiobookShelf 与共享层复制“连接/库/详情”，新增源会线性放大维护面。

MID 主题双代码路径

UIKit Themeable.applyTheme 与 SwiftUI ThemeViewModel 两套需手动同步；深色模式窗口级强制，无法按页面定制。

MID ItemListView 巨型文件

集中工具栏/多选/排序/拖拽/搜索/文件夹创建，改动风险高。

MID Pro / 付费墙散落

锁定主题、Pro 横幅、showPro() 在多处重复，付费墙入口未集中。

LO 默认视觉偏“工具感”

原版以纯色/系统灰为主、缺少渐变与衬线层次，被指“不够清新优雅”——本轮以新默认主题与留白解决。

03重规划目标与设计原则

目标

  • 消除 UIKit/SwiftUI 双外壳冗余
  • 统一清新优雅设计语言
  • 播放器回归合理垂直结构
  • 收敛媒体服务器与付费墙重复
  • 降低单文件复杂度

设计原则

  • 清新优先：柔色 + 留白 + 衬线层次
  • 结构合理：保留原版有效布局
  • 单一令牌源：一套配色/间距/字体
  • 协议化复用：媒体源/付费墙抽协议
  • 渐进迁移：按阶段落地

保留的核心

  • “纯粹有声书播放器”定位
  • 文件夹/播放列表、拖拽排序
  • 章节、书签、智能回退、睡眠定时器
  • Hardcover / Jellyfin / AudiobookShelf
  • CarPlay / Watch / 小组件生态

04信息架构与导航重构

让 MainView 成为真正的根，由 AppNavigationController 直接寄宿，删除死 UIKit 外壳；搜索提升为全版本常驻 tab；媒体源经统一“资料来源”中枢接入。

✕ 当前

UIKit RootViewController 根 → 全屏模态盖 MainView；搜索仅 iOS 26 为 tab；媒体源散落两处。

✓ 建议

AppNavigationController 直接寄宿 MainView。四 tab：📚 图书馆 · 🔍 搜索 · 👤 账户 · ⚙️ 设置。播放器为常驻上滑 sheet；媒体源经“资料来源”中枢。

令牌层（单一真相源）

  • 颜色：新增语义别名 colorSurface / colorAccent / colorMuted，UIKit 与 SwiftUI 共用 SimpleTheme 解析。
  • 间距：重命名为递增刻度 space1=4 … space8=48。
  • 圆角/阴影：radiusLg=24 / radiusMd=16，统一柔和投影。
  • 封面：渐变质感（青绿→暖金），替代纯色块，呼应参考原型。

组件库（一处定义，处处复用）

  • PrimaryButton、ThemedSection / ListRow
  • ArtworkView（渐变封面 + 衬线书名）
  • ProgressIndicator（线性/环形合一）
  • MediaActionBar（底部 5 动作统一样式）
  • PaywallView、SourceConnector

06关键界面重设计（清新优雅原型）

三块原型均已改为清新风，且播放器布局已按原版修正：大封面（书名印其上）→ 章节导航行 → 进度 → 传输行 → 底部 5 个快捷动作。点击书封可展开播放器，右上角可切日夜。

① 图书馆（Library）—— 清新网格

✕ 当前

单一列表；排序/筛选藏工具栏菜单；ItemListView 巨型文件。

✓ 清新版

渐变封面网格 + 衬线书名；顶部筛选胶囊（全部/在听/已下载/已读完）；底部迷你播放器；列表/网格可切换。ItemListView 拆为工具栏/列表/多选/sheet 四模块。

② 播放器（Player）—— 布局修正 + 清新

✕ v1 问题

把“快退/睡眠/书签/快进/倍速”塞进一个玻璃条，元素拥挤、主次不清，不如原版。

✓ v2 修正

回归原版垂直结构：大封面（悬浮+书名其上）→ 章节导航行（‹ 章名 ›）→ 进度+时间 → 传输行（后退/播放/前进）→ 底部 5 动作（倍速/睡眠/书签/章节/更多）。加波形可视化与柔和渐变背景。

③ 设置（Settings）—— 分组 + 清新

✕ 当前

巨型 Form；Pro 横幅散落；媒体源入口分散。

✓ 清新版

顶部 Pro 卡；分组：外观 / 资料来源（统一媒体服务器）/ 播放 / 其他。柔和卡片 + 衬线标题。

07跨平台一致性

Watch 与 CarPlay 是相对独立的 UI 面，但应与 iOS 共享同一套清新设计令牌，避免三套配色各自为政。

平台现状建议
小组件SwiftUI WidgetKit，独立 Assets复用 SimpleTheme 令牌；最近播放/控制组件与 iOS 播放器视觉对齐
Watch近独立 watchOS 应用经 BookPlayerWatchKit 共享令牌与列表/播放行组件
CarPlay独立 CPList/CPNowPlaying 模板保留模板化（CarPlay 约束所致），数据源与图标语义与 iOS 一致
分享扩展UIKit ShareViewController迁移 SwiftUI 或至少套用统一令牌

08实施路线图（分阶段、低风险）

渐进式迁移，每阶段可独立交付。

阶段范围关键改动风险
Phase 0
外壳简化		导航删除 RootViewController/Main.storyboard，MainView 由 AppNavigationController 直接寄宿低

遗留迁移		Loading / Import迁至 SwiftUI（已有 LoadingOverlayState/ImportManager 原语）中
Phase 2
设计令牌		设计系统落地清新默认主题 + 统一排版/间距/圆角令牌，收敛主题双路径中
Phase 3
图书馆		Library渐变封面网格/列表切换、筛选、长按快捷；拆分 ItemListView中
Phase 4
播放器		Player布局修正为垂直结构 + 清新渐变封面/波形/底部动作条低
Phase 5
设置 / 来源		Settings分组化；媒体源经“资料来源”中枢 + IntegrationProtocol中
Phase 6
账户 / 付费墙		Profile / Pro合并登录/Passkey；付费墙集中为 PaywallView中
Phase 7
跨平台		Watch / Widget共享设计令牌；小组件视觉对齐低

交付说明：本方案基于 TortugaPower/BookPlayer 源码静态盘点 + 参考原型 Lumina Listen 的清新优雅基调。播放器布局严格对照真实 PlayerView.swift（封面 → 章节导航 → 进度 → 传输行 → 底部 5 动作）重建。原型为 CSS 高保真示意，可点击交互（展开播放器 / 切日夜）。

下一步可就 Phase 4（播放器清新化）或 Phase 2（设计令牌落地）深入为 PR 级改动方案。
